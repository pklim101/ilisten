# 成片静音/字幕错位问题诊断与经验沉淀

> 日期：2026-11-04 | 关联：剑19 Test1 Part1 成片 01:48~02:54 区段
> 结论：**非静音、非素材问题，是 01_align.py 词级对齐的"锚点错位"缺陷。**

---

## 一、现象

成片 `c19_test1_part1.mp4` 在 **01:48~02:54（约 66 秒）** 区间内，画面有字幕（三态字幕正常轮换），但几乎听不到对应人声。

## 二、根因定位（逐步排查过程）

### 1. 排除"纯静音"假设
用 ffmpeg `volumedetect` 检测原始音频 54.6~113 秒区间：

```
mean_volume: -33.1 dB   max_volume: -11.1 dB
```

`max_volume -11.1dB` 与整段音频（-11.1dB）持平，说明**这段其实有人声**，不是静音。问题不在素材，而在"字幕时长被人为拉长，覆盖了不该覆盖的区间"。

### 2. 锁定异常句子
成片时间轴 `timeline.json` 中，`sentence_index=4` 这句：

```
"My name's John Chapman, and I'm a teaching assistant at a local primary school."
原始音频区间：54.6s ~ 113.04s   →  时长 58.4 秒（！）
```

一句正常自我介绍被对齐成了 58 秒，它才是问题所在。这句三遍循环正好铺满了成片的 108~174 秒区间（即 01:48~02:54）。

### 3. 词级时间戳暴露真相
`sentences.json` 里 index=4 的词级对齐：

| 词 | start | end |
|---|---|---|
| a | 54.6 | 54.8 |
| teaching | 54.8 | 55.1 |
| assistant | 55.1 | 55.66 |
| at | 61.28 | 61.5 |
| **a** | **113.04** | **113.04**  ⚠️ |
| **school** | **113.04** | **113.04** ⚠️ |

- 前 4 个词时间连续正常（54.6 → 61.5 秒）
- 最后 2 个词 `a`、`school` 突然跳到 **113.04 秒**，中间出现 **52 秒空档**
- 113.04 秒恰是下一段题目说明段 `"Okay, what would you like to know?"` 的起点

### 4. 缺陷机理（01_align.py）

`align()` 用 `difflib.SequenceMatcher` 做整篇序列对齐，取每句的 **`start = 首个匹配词的 start`、`end = 末个匹配词的 end`** 作为句子边界。

当 whisper 把句中某短语（`local primary`）**漏转写/错配**、而结尾词 `school` 因在正文和题目说明中重复出现（"school" 是高频词）被 `SequenceMatcher` 匹配到了**后面另一处** `school` 时：

- 末词锚点被拉到 113.04 秒
- 句子时长被错误放大为 58 秒（真实约 7 秒）
- 该句三遍循环后，成片多出约 51×3 ≈ 153 秒的"有字幕、无人声"区段

**本质**：当前对齐把"词序匹配"直接等同于"时间连续正确"，缺少"同句内词时间戳必须连续、跨度必须合理"的校验。

---

## 三、避免再犯的防御措施（按优先级）

### 立即：增加对齐合理性校验（改 01_align.py）

1. **句内跨度校验**：对每句 `end - start`，若超过阈值（建议 15 秒，Part 独白长句一般 <12 秒）则判为异常，不采纳该句边界。
2. **词间跳变检测**：同句内相邻词的时间间隔若 > 阈值（建议 2 秒，正常语速词间 <0.5 秒），说明中间发生错配，应从该处断开，只保留连续的前段。
3. **末词锚点去噪**：句子 `end` 优先取"最后一个**时间连续**的词"，而非"最后一个匹配到的词"——即从末词往前回溯，遇到时间跳变即截断。

### 流程：出片后自动质检（低成本、高价值）

新增质检脚本或并入 run.sh 第 6 步，成片后自动检查：

- 每个字幕事件 `end - start` 是否超过合理上限（如 > 20 秒报警）
- 全文是否存在"字幕持续但对应音频段 near-silent"的区段（可用 ffmpeg 分段 volumedetect）
- 命中即打印告警，不阻断出片，但提醒人工复核

### 人工：抽帧 + 抽听双检查

- 视频交付前，除抽帧看字幕外，**随机抽 2~3 个时间点听音频**（尤其长句、开头句）
- 重点关注"字幕停留时间明显偏长"的位置

### 模型：评估 whisper 模型选型影响

本次用的是 `small` 模型。回顾 PRD 版本演进记录：V2 曾用 `medium` 模型因"边界漏转写"被否决、回退 `small`。说明该素材下词级对齐本身对模型敏感。建议：
- 保留 `small`（当前稳定基线）
- 若某篇对齐成功率异常低（如 <80%），再单独尝试 `medium` 对比，而不是全局切换

## 四、本次成片的处理建议

该成片 01:48~02:54 区段受影响，**建议重跑**（在 01_align.py 修复后），避免带缺陷上传。重跑成本极低（全自动，约 5 分钟）。（已重跑修复，见第六节）

---

## 五、一句话总结

> **词级时间戳里，最后一个词不一定是句子的真实结尾——高频词（school、the、a）会被 SequenceMatcher 错配到几秒甚至几十秒后的同名位置，把句子边界错误拉长。对齐必须校验"句内时间连续性"，而不能只信"词序匹配"。**

## 六、后续：第一版修复的"误伤"与自适应阈值（2026-11-05）

### 现象
生成剑19 Test1 Part3 时发现，第一版修复的固定阈值（单句 ≤15s、词间隔 ≤2s）把 Part3 里两句长对话误伤了：

| 句子 | 词数 | 结果 |
|---|---|---|
| "Yeah, I'd used that before... what I managed to produce." | 49 词 | 判 matched=False |
| "One thing I've noticed is the number of branded products..." | 37 词 | 判 matched=False |

未匹配的句子不会被循环播放、也不会有字幕，反而被 `extract_instructions()` 归入"题目说明段"只播一遍——**从"静音错位"变成了"内容丢失"，是更隐蔽的回归**。日志里的信号是：题目说明段从应有的 4 个涨到 6 个，且其中两段文本明显是正文对话。

### 二次修复（当前版本）
阈值改为**按句子词数自适应**：

- `MAX_WORD_GAP_SEC` 2s → **5s**：真正的锚点错位是几十秒级跳变（本次 52s），5s 足以拦截；2s 会误切正常语流中的停顿
- 单句时长上限：`max(15s, 词数 / 2.2 × 1.5 + 3s)`，即长句按语速估算合理时长。49 词句上限约 36s，实测真实时长 17.2s，正常通过
- 固定 15s 保留为短句的绝对下限兜底

### 验证结果（Part3 重跑）
- 对齐 62/66 → **64/66**（剩余 2 句是原文孤立句号切分残片，无害）
- 题目说明段 6 → **4 个**，误判消失
- 两句长对话词覆盖完整（首尾词齐全，未被截断）
- 字幕事件 162 → **168**，最长事件 17.2s，无超长事件

### 新增经验

1. **阈值不能用固定秒数一刀切**：Part1/Part2 独白句短，Part3 讨论长句可达 20s 以上；按词数估算才是跨 Part 通用的做法
2. **"未匹配"不等于"可丢弃"**：未匹配句会被归入题目说明段只播一遍、无字幕，属于静默的内容丢失。应在对齐日志里对"未匹配句数 / 说明段文本疑似正文"做显式告警
3. **回归验证要跨题型**：修完一个 bug 后，用不同 Part（对话 vs 独白）各跑一篇验证，防止修复本身引入新问题
4. **日志里的异常信号**：`说明段数量突然变多`、`说明段文本是完整对话句`、`对齐率低于 90%` 三者任一出现，都应停下来看对齐结果再出片

## 七、附：Part4 原文含 ANNOUNCER 指令行（2026-11-07）

### 现象
剑19 Test1 Part4 原文首尾各有一行 `ANNOUNCER: ...`，内容是考试指令（"You will hear..." / "That is the end of Part 4..."），属于题目说明段而非正文。

原 `load_original_text()` 只过滤以 `PART/SECTION/Test` 开头的行，这两行会被当成正文句参与循环 3 遍并配三态字幕——违反"说明段原样播放一遍、不显示字幕"的产品规范，还会挤掉后续的说明段识别。

### 修复
`01_align.py` 的 `load_original_text()` 增加过滤：

```python
not re.match(r"^\s*(ANNOUNCER|NARRATOR)\s*:", line, re.IGNORECASE)
```

即：以 `ANNOUNCER:` / `NARRATOR:` 开头的行一律从正文输入中剔除，由音频空隙自动识别为说明段。

### 验证（Part4）
- 38/38 句全部匹配、0 未匹配
- 说明段识别为 3 段：开头 84.6s（含读题静音）、中段 5.4s 停顿、结尾 46.7s
- 开头说明段抽帧确认**无字幕**，正文段抽帧确认挖空态字幕正常

### 经验
1. **不同 Part 的原文格式不统一**：Part1/3 只有 `PART N` 标题行 + 说话人标签（`SALLY:`/`COLIN:`），Part4 多了 `ANNOUNCER:` 指令行。输入过滤规则要按"最宽松的真实素材"设计，不能假设格式一致
2. **说话人标签 vs 指令标签要区分**：`SPEAKER:` / `COLIN:` 是正文的一部分（whisper 不转写标签但句子会正常对齐），`ANNOUNCER:` 整行都是指令，两者不能一刀切过滤
3. **新增素材先跑一次步骤1看日志**：出片前用 `01_align.py` 单独跑一遍，检查"切分句数 / 匹配率 / 说明段文本"，比整条流水线跑完才发现问题便宜得多

## 八、附：省略号被切句器切碎成「孤立句号残片」（2026-11-09）

### 现象
剑19 Test2 Part3 首次出片后 QA 判 **BLOCK**：对齐率 `69/78 = 88.5%`（< 90%）、
1 句完整内容静默丢失（`BELLA: OK .`）。查 `data/sentences.json`，9 句未匹配里
**8 句是单独的 `.`、1 句是 `BELLA: OK .`**，全部同源；说明段 [3] 还把结尾对话
`Absolutely. So let's discuss ...` 并了进去（396.9~410.8s，13.9s）。

### 根因
官方 tapescript 用 `. . .`（**空格分隔的省略号**）表示停顿 / 话没说完，而切句器是：

```python
parts = re.split(r"(?<=[.!?])\s+", text)
```

每个点后面都跟着空格，于是 `OK . . . and the leather ankle boots.` 被切成
`BELLA: OK .`、`.`、`.`、`. and the leather ankle boots.` 四段。碎片句既拉低
对齐率分母，又让 `BELLA: OK .` 被 QA 判成「完整内容静默丢失」。

该问题在 `c19_test2_part1` 就出现过（基线 note 记着「4 个未匹配均为孤立句号残片」），
只是当时 81/85 = 95.3% 没跌破 90%，没被拦下。对话密集的 Part3 省略号更多，才暴露。

顺带辨析：阶段 1.5 的 ASR 差异 `audio: how we're going to split up the presents`
**不是漏句**，而是 whisper 对结尾淡出音频的幻觉补全；联网原文明确注明官方文本以
`So let's discuss . . .` 结尾。**不要把 ASR 幻觉补进原文**——铁律 15 说音频是真值源，
但淡出段本身没有可核对的真值。

### 修复
`split_original_sentences()` 在切句前先把省略号归一化成 Unicode `…`：

```python
text = re.sub(r"\.\s*\.\s*\.", "…", text)
parts = re.split(r"(?<=[.!?])\s+", text)
```

`…` 不属于 `[.!?]`，不会触发切分；`normalize()` 又把非字母数字字符当空格
（省略号不发音、whisper 也不转写），不影响词级对齐。

### 验证
- **全量回归**：新旧两种切句器跑 `resource/` 全部 7 篇原文。
  无省略号的 4 篇（test1_part1 / test1_part2 / test1_part4 / test2_part2）**句数零变化**；
  含省略号的 3 篇 test1_part3 -3、test2_part1 -6、test2_part3 -11 句，
  减少的全是 `.` 碎片（纯改善），确认影响面后才敢动生产脚本。
- **part3 重跑**：67/67 = 100% 全对齐、0 未匹配、碎片 8→0；
  QA **17 PASS / 0 WARN / 0 BLOCK**；3 张抽帧（挖空 / 双语 / 说明段）全部通过。
- 成片 19:53 / 64.1MB / 189 字幕事件 / 149 考点。

### 经验
1. **省略号不是句末标点**：切句规则必须先归一化 `. . .` / `...`，再按 `[.!?]` 切。
2. **QA 阈值只兜症状，根因要去查切句器**：看到「孤立句号残片」不要调阈值、不要盲重跑
   （04 排障明确禁止对内容缺陷自动重试）。
3. **先跑步骤 1 再跑整条流水线**：本篇多花了 7 分钟 + 一次 67 句 LLM 标注费才定位，
   单独跑 `01_align.py` 看「切分句数 / 匹配率 / 说明段文本」几十秒就能发现。
4. **改通用脚本前必做全量回归**：用新旧逻辑对比所有已有原文，确认零影响面才落盘。

## 九、QA 固定 20s 阈值误伤 Part4 学术长句（2026-11-09）

**现象**：`c19_test2_part4`（缓步动物讲座）出片后 `qa_check.py` 判 `BLOCK`：
「3 个 >20s 超长事件，最长 22.2s（锚点错位）」，其余 16 项全 PASS。

**诊断**（先查数据，不调阈值）：3 个超长事件其实是**同一句** 45 词长句
`There's been some interesting research ... which is incredibly hot.` 在三遍里各占 22.2s；
对齐率 39/39 = 100%、0 未匹配句、说明段无正文混入；C7 人声兜底
`max_volume -10.8dB`（有人声，不是「有字幕无人声」）。按 `01_align.py` 已采用的
语速模型（2.2 词/秒 × 1.5 + 3s）这句合理上限为 **33.7s**，22.2s 完全正常。
根因是 `qa_check.py` 的 C1 仍用固定 `MAX_EVENT_SEC=20`，而 `01_align.py` 早在
Part3 长对话时就改成按词数自适应了——两处判据不同源。

**修复**：C1 改为 `event_max_sec(n_words) = max(20, n_words/2.2×1.5+3)`，
与 `01_align.sentence_max_sec()` 同源；取不到原文词数时退化为固定 20s；
20s 下限保留，短句被锚点错位拉长照样 BLOCK。C7 人声兜底继续独立执行。

**回归**（改动前必做）：`resource/` 全部 8 篇原文的最长句词数 → 上限全部合理
（22 词仍 20s；45 词 33.7s）；5 个反例中「10 词/25s」「20 词/30s」
「45 词/40s」「0 词/25s」仍判 BLOCK，只有「45 词/22.2s」放行。
重跑本篇质检 **17 PASS / 0 WARN / 0 BLOCK**，3 帧 ViewImage 全部通过。

**教训**：固定阈值误伤长句这个坑会以不同形态复现（先是 `01_align.py` 的 15s，
再是 `qa_check.py` 的 20s）。**发现超长事件先查「对应原文词数 + 对齐率 + 人声兜底」，
三条都正常才是规则缺陷；修规则必须与对齐脚本同源、保留下限、做全量回归，
绝不直接把阈值调大放行。**
