## 1. 背景与目标

### 1.1 问题背景

雅思听力备考中，"逐句精听 + 填空式回忆"是被验证有效的训练方式。手工制作这类视频（对齐音频切句、逐句重复三遍、标注考点词、加字幕）耗时极长：一段 5 分钟的 Part2 音频，人工剪辑 + 字幕制作通常需要 2～3 小时。

### 1.2 产品目标

把「雅思听力音频 + 原文文本」两个输入，自动生成为可直接发布的**逐句精听学习视频**，完整还原考试音频节奏，无需人工剪辑。

### 1.3 目标用户

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 雅思备考者（主要） | 日常精听训练 | 逐句反复听、考点词填空回忆、中英对照 |
| 雅思老师 / 内容创作者（次要） | 批量产出教学素材 | 一次配置、批量出片 |

### 1.4 成功标准

- 音频内容**零遗漏、零改动**（原始考试音频完整保留）
- 正文句**逐句循环 3 遍**，三态字幕与音频严格同步
- 题目说明/考试指令段**原样播放**，不重复、不显示字幕
- 单篇（约 5.5 分钟素材）全自动出片，无需人工干预

## 2. 需求范围

### 2.1 输入

| 输入 | 格式 | 说明 |
|---|---|---|
| 音频文件 | `.mp3` / `.m4a` / `.wav` | 完整考试音频（含题目说明、读题静音） |
| 原文文本 | `.md` / `.txt` | **仅正文**，不含题目说明；与音频同名同目录 |

> 原文文本要求：纯正文段落，句末以 `.!?` 结尾用于切句。文件内以 `PART`/`SECTION`/`Test` 开头的行会被自动过滤。

### 2.2 输出

| 输出 | 规格 |
|---|---|
| 成片 `.mp4` | 1920×1080 (16:9)，H.264 + AAC，25 fps |
| 时长 | 由素材决定（示例：素材 5.5 min → 成片 18 min 33 s） |
| 体积 | 示例成片 61.6 MB |

### 2.3 不在范围内（明确排除）

- ❌ **不加片头片尾**（用户明确要求，V2 版本因私自加片头片尾被否决）
- ❌ **不裁剪、不改动原始音频内容**
- ❌ 不做口语/写作/阅读等其他题型
- ❌ 不做视频变速、音效、BGM
- ❌ 不做交互式播放器（输出为线性视频）

## 3. 核心功能需求

### 3.1 音频分段：区分「题目说明段」与「正文句」

音频中包含两类内容，处理方式完全不同：

| 类型 | 内容 | 处理方式 |
|---|---|---|
| **题目说明段** | "Part 2. You will hear…"、"…you have some time to look at questions"、"That is the end of part two…"、以及中间的**读题静音** | **原样播放一遍**，不循环、**不显示字幕** |
| **正文句** | 听力正文的每个句子 | **逐句循环 3 遍** + 三态字幕 |

**判定规则**：用原文（纯正文）对齐音频转写后，正文句时间范围之外、且长度 ≥ `GAP_THRESHOLD`（默认 4.0 秒）的空隙，识别为题目说明段。

> 为什么是 4.0 秒：正常句间停顿 < 3 s，题目说明/读题静音段通常 > 5 s，4.0 是安全分界。

### 3.2 正文句三遍循环（核心交互）

每一句正文连续播放 3 遍，每遍字幕呈现不同形态，形成"听写 → 核对 → 理解"的学习闭环：

| 遍次 | 字幕形态 | 设计意图 |
|---|---|---|
| **第 1 遍** | **挖空态**：考点词替换为红色下划线 `______`，其余词正常显示 | 强迫回忆、主动听辨考点 |
| **第 2 遍** | **全文高亮态**：完整原文，考点词用橙色高亮 | 核对答案、强化视觉锚点 |
| **第 3 遍** | **双语态**：完整英文 + 下方中文翻译 | 理解语义、建立中英映射 |

### 3.3 停顿节奏（严格与音频一致）

| 停顿位置 | 时长 | 字幕行为 |
|---|---|---|
| 三遍之间 | **1 秒** | **字幕保持显示**（不闪烁消失） |
| 每句三遍结束后 | **3 秒** | 进入下一句前留出消化时间 |

> 关键：停顿期间字幕**保持显示**，避免字幕闪烁打断学习节奏。

### 3.4 考点词标注

由 LLM 从每句中挑选 **1～5 个**"考点片段"，原则：

- 数字、日期、金额、地名、人名、专有名词
- 重点实义词、固定搭配、短语动词
- 连读/弱读/吞音导致易听错的词或短语

**硬约束**：每个考点片段必须是原句的**连续子串**（保证能精确高亮/挖空）。

### 3.5 视觉规格

| 项 | 规格 |
|---|---|
| 背景 | 清新自然风景图（淡蓝天空 + 白云 + 田野水面），铺满画面**无黑边** |
| 英文字幕 | Arial 48 号，深色 `&H00202020`，白色描边 |
| 中文翻译 | Arial 36 号，深灰 `&H00404040` |
| 考点词高亮 | 橙红色 `&H000080FF`（浅色背景上比黄色更醒目） |
| 挖空下划线 | 红色 `&H000000C0`，单条连续下划线 |
| 字幕定位 | **垂直 + 水平居中**（画面正中） |
| 左右内边距 | **≥ 120 px**（实际要求 ≥ 50 px，实现取 120 px 留足余量） |

### 3.6 批量处理

支持扫描目录下所有音频 + 同名原文，逐个全自动出片，输出成功/失败统计。

## 5. 版本演进

| 版本 | 主要变更 | 结果 |
|---|---|---|
| **V1** | MVP：small 模型、纯色背景、每句 ×3 遍 + 3 s 停顿，无题目说明区分 | 基线可用 |
| **V2** | 优化挖空 + 批量脚本 + medium 模型 + 渐变背景 + 片头片尾 | ❌ **被否决**：medium 模型边界漏转写 + 私自加片头片尾，效果不如 V1 |
| **V3** | 区分题目说明/正文；指令 1 遍 + 正文 3 遍（1 s/3 s）；清新背景；深色字幕；**无片头片尾**；回退 small 模型 | ✅ 当前版本 |
| **V3.1** | 修复挖空下划线重叠；字幕垂直居中；**手动折行修复长句左右裁切**，内边距 120 px；去水印；背景铺满 | ✅ 用户确认"很符合预期" |

## 6. 约束与风险

| 类别 | 说明 |
|---|---|
| 素材依赖 | 原文必须是**纯正文**，混入题目说明会导致对齐错乱 |
| 外部依赖 | DeepSeek API（翻译/标注）、HuggingFace（whisper 模型首次下载） |
| 网络 | 国内需配置 HF 镜像，否则模型下载失败 |
| 资源 | 合成步骤内存占用高，需后台运行避免 OOM |
| 成本 | 每篇约 43 句 → 5 次 DeepSeek 调用（每批 10 句） |
| 密钥安全 | ⚠️ `02_annotate.py` 中硬编码了 API Key 默认值，存在泄露风险（详见维护文档） |
