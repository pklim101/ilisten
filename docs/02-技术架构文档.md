## 1. 系统概览

### 1.1 整体架构

```
输入                     流水线（5 步串行的离线批处理）                    输出
─────                   ────────────────────────────────────              ─────
音频.mp3 ─┐
          ├─→ [01] 对齐 ─→ [02] LLM标注 ─→ [03] 音频重组 ─→ [04] 字幕 ─→ [05] 合成 ─→ 成片.mp4
原文.md  ─┘      │            │              │  ┌──────┘        │             │
              sentences   annotated      rebuilt   timeline    subtitles      │
                .json      .json        _audio.mp3  .json        .ass         │
              instructions.json                                              │
                                                              背景图.png ────┘
```

**架构特征**：
- **离线批处理流水线**，5 个独立脚本串行，通过 JSON 中间产物解耦
- **无服务、无数据库、无状态**，每个脚本可单独重跑（输入产物存在即可）
- **FFmpeg 为唯一重资产依赖**，通过 `imageio-ffmpeg` 静态二进制提供（含 libass）

### 1.2 中间产物契约

| 文件 | 生产者 | 消费者 | 内容 |
|---|---|---|---|
| `sentences.json` | 01 | 02, 03 | 正文句数组：`{index, text, start, end, words[], matched}` |
| `instructions.json` | 01 | 03 | 题目说明段：`{start, end, text}` |
| `annotated.json` | 02 | 03 | 句子 + `translation` + `highlights[]` |
| `rebuilt_audio.mp3` | 03 | 05 | 重组后音频 |
| `timeline.json` | 03 | 04 | 字幕事件时间轴 + 全局参数 |
| `subtitles.ass` | 04 | 05 | 三态 ASS 字幕 |

## 2. 技术选型与决策依据

### 2.1 选型总表

| 领域 | 选型 | 备选 | 决策依据 |
|---|---|---|---|
| 语音转写 | **faster-whisper `small`** | medium | ⚠️ **medium 效果更差**：在"正文↔题目说明"边界处会漏转写短句（实测 index 22 等短句被压成 0.32 s）。small 边界转写更完整 |
| 序列对齐 | `difflib.SequenceMatcher` | 动态规划自研 | 标准库、鲁棒，能容忍 whisper 转写与原文的差异（标点/大小写） |
| LLM 标注 | DeepSeek `deepseek-chat` | 本地模型 | JSON 结构化输出稳定、成本低；temperature=0.2 保证确定性 |
| 字幕格式 | **ASS (libass)** | SRT | SRT 不支持颜色/下划线/定位样式，无法满足三态渲染 |
| FFmpeg | **imageio-ffmpeg** 静态二进制 | brew/conda 安装 | ⚠️ brew/conda 安装在沙箱环境被拦截；imageio-ffmpeg 自带**含 libass** 的 ffmpeg 7.1，pip 即可得 |
| 折行策略 | **Python 手动折行** | libass `\q2` 自动折行 | ⚠️ libass 的 `\q2` 在本环境**不可靠**：长句不折行而是超出画面被裁切。改为手动计算插入 `\N` |
| 图像处理 | PIL + numpy | OpenCV / scipy | 环境无 cv2/scipy，PIL 高斯模糊即可满足去水印需求 |

### 2.2 关键决策：为什么必须手动折行

**问题**：长句（如 "Don't try to do too much that first evening…"）在成片中左右两端被裁切。
**排查**：增大 `MarginL/MarginR` 无效；`\q2` 自动折行未触发。
**根因**：libass 的自动折行在 `imageio-ffmpeg` 打包版本中未按 `Margin` 约束行宽，长句被视作单行渲染后水平溢出。
**方案**：在 Python 侧估算渲染宽度并手动插入 `\N` 硬换行，完全绕开 libass 折行行为。

## 3. 模块详细设计

### 3.1 `[01] 01_align.py` — 音频对齐与分段

**职责**：转写音频 → 对齐原文 → 切出正文句时间戳 → 识别题目说明段。

**流程**：
1. 加载原文，`load_original_text()` 过滤 `PART/SECTION/Test` 开头的行
2. `split_original_sentences()` 按 `(?<=[.!?])\s+` 切句
3. `transcribe()` 用 faster-whisper 转写，`word_timestamps=True` 取词级时间戳
   - `device="cpu"`, `compute_type="int8"`, `cpu_threads=min(cpu,4)`
4. `align()` 用 `difflib.SequenceMatcher` 把原文 token 序列对齐到 whisper token 序列
   - 取 `equal` opcode 建立 `orig→whisper` 索引映射
   - 每句的 start/end 由其首/末匹配词的时间戳决定
   - **插值兜底**：未匹配但夹在两个已匹配句之间、且空隙 `0.5 < gap < 6.0` 的句子，用相邻时间插值
5. `extract_instructions()` 扫描正文句时间范围外的空隙，≥ `GAP_THRESHOLD` 的识别为题目说明段

**关键参数**：
```python
MODEL_SIZE = "small"          # WHISPER_MODEL
GAP_THRESHOLD = 4.0           # 判定题目说明段的最小空隙（秒）
```

**实测输出**（示例素材）：43 句全部匹配成功，识别 4 个题目说明段（含开场指令、读题静音、结尾指令）。

---

### 3.2 `[02] 02_annotate.py` — LLM 标注

**职责**：调 DeepSeek 为每句产出中文翻译 + 考点词列表。

**设计要点**：
- **分批处理**：`BATCH = 10` 句/次请求，减少调用次数
- **结构化输出**：`response_format={"type": "json_object"}`，`temperature=0.2`
- **降级容错**：JSON 解析失败时该批降级为空标注（`translation:""`, `highlights:[]`），不中断整条流水线
- **未匹配句补齐**：无时间戳的句子也写入产物（不参与成片）

**Prompt 约束（关键）**：
> 每个 highlight 必须原样出现在原句中（是原句的连续子串），返回时保持原句中的大小写和形式。

> 🔐 **安全要求**：`API_KEY` 必须通过 `DEEPSEEK_API_KEY` 环境变量提供，脚本在缺失时直接报错退出，**禁止硬编码**（避免密钥随代码提交泄露）。

### 3.3 `[03] 03_rebuild_audio.py` — 音频重组

**职责**：按"指令 1 遍 + 正文 ×3 遍"重新拼音频，并生成字幕时间轴。

**算法**：
```
segments = 指令段列表 + 正文句列表，按 start 时间排序交织
cursor = 0
for (kind, item) in segments:
    if 指令段:
        切片 [start,end] → 追加音频；cursor += 时长
    else 正文句:
        for rep in 0..2:
            记录 timeline 事件 {repeat: rep, start: cursor, end: cursor+句长, text, highlights, translation}
            追加该句音频切片；cursor += 句长
            if rep < 2: 追加 1s 静音；cursor += 1.0
        if 非最后一句: 追加 3s 静音；cursor += 3.0
```

**切片实现**：`ffmpeg -ss {start} -t {dur} -i audio -acodec libmp3lame -q:a 2`
**静音生成**：`ffmpeg -f lavfi -i anullsrc=r=44100:cl=mono -t {dur}`
**拼接**：`ffmpeg -f concat -safe 0` + 文件列表（**必须用绝对路径**，相对路径会失败）

**关键参数**：
```python
REPEATS       = 3      # 每句遍数
REPEAT_GAP_SEC = 1.0   # 三遍之间停顿
SENT_GAP_SEC   = 3.0   # 每句三遍后停顿
MIN_SENT_SEC   = 0.5   # 过滤异常短句（防 whisper 边界抖动产生 0.3s 碎片）
```

> **注意**：字幕事件 `end` 只覆盖音频段，不含后续停顿；但**下一遍字幕紧接着出现**，因此视觉上停顿期间上一遍字幕会保持到下一遍开始 —— 这实现了"停顿期字幕保持显示"。

### 3.4 `[04] 04_subtitles.py` — 三态 ASS 字幕生成

**职责**：把 timeline 渲染为三态 ASS 字幕。

#### 3.4.1 样式定义

```ass
Style: EN,Arial,48,&H00202020,...,&H00FFFFFF,...,1,4,0,5,120,120,40,1
Style: ZH,Arial,36,&H00404040,...,&H00FFFFFF,...,1,3,0,5,120,120,40,1
```
| 字段 | 值 | 含义 |
|---|---|---|
| `PrimaryColour` | `&H00202020` / `&H00404040` | 深色正文（**BGR 格式**） |
| `OutlineColour` | `&H00FFFFFF` | 白色描边（浅色背景上保证可读） |
| `Alignment` | `5` | 居中（配合 `\an5`） |
| `MarginL/R` | `120` | 左右内边距（既用于折行宽度，也保证 ≥50px 要求） |
| `Outline` | EN `4` / ZH `3` | 描边宽度 |

#### 3.4.2 三态渲染

**第 1 遍 — 挖空态**
```python
n_words = max(1, len(seg.split()))
underline_len = min(6 * n_words + 2, 14)   # 每词约 6 个下划线，长短语封顶 14
"{\u1\c&H000000C0&}" + "_"*underline_len + "{\u0\c&H00202020&}"
```
> **修复要点**：早期版本用 `"\u2003" + "____"`（em space 分隔）生成多条下划线，libass 折行时下划线作用范围错乱、与相邻词/句号重叠。改为**单条连续下划线 + 普通空格分隔**后解决。

**第 2 遍 — 全文高亮态**
```python
"{\c&H000080FF&}" + seg + "{\c&H00202020&}"   # 橙红高亮 + 恢复深色
```

**第 3 遍 — 双语态**
```
英文 + "{\rZH}" + "\N" + 中文      # \rZH 切换中文样式，\N 硬分行为英文上、中文下
```

#### 3.4.3 手动折行（核心修复）

```python

    # 忽略 ASS 标签 {...}，英文 0.52×字号 / 中文 1.0×字号 / 空格 0.28×字号
def wrap_text(text, fontsize, max_width):
    # 在空格处折行，返回用 \N 连接的多行
```

**解耦顺序（关键）**：
```
先对【纯文本】折行 → 再【逐行】应用高亮标签
```
> 若先加标签再折行，高亮标签 `{\c...}` 会被换行切断，导致第 2 行颜色异常。必须先折行后高亮。

**可用宽度**：`MAX_W = VIDEO_W - 2*120 = 1680 px`

### 3.5 `[05] 05_compose.py` — 合成出片

**职责**：背景图 + 音频 + 烧录字幕 → MP4。

**滤镜链（单视频流，无片头片尾）**：
```
[0:v] scale=1920:1080:force_original_aspect_ratio=increase, crop=1920:1080, setsar=1 [bg];
[bg]  ass=subtitles.ass [v]
```

> **修复要点**：早期用 `force_original_aspect_ratio=decrease + pad`，因背景图为 3:2 (1536×1024)，缩放后左右各留 150 px 黑边，字幕延伸到黑边看起来"超出背景"。改为 `increase + crop` 后背景**铺满全画面**。

**编码参数**：
```
-c:v libx264 -preset medium -crf 20 -pix_fmt yuv420p
-c:a aac -b:a 192k
-t {audio_duration}
```

> ⚠️ 历史坑：曾使用 `eq=brightness=0.82` 压暗背景，但该参数是**加性偏移**，导致浅色背景过曝全白。已移除，改用深色字幕 + 白描边适配浅色背景。

## 4. 关键技术要点与踩坑记录

| # | 问题 | 根因 | 解决 |
|---|---|---|---|
| 1 | brew/conda 装 ffmpeg 失败 | 沙箱拦截 | 改用 `imageio-ffmpeg`（pip，自带 libass 的 ffmpeg 7.1） |
| 2 | HF 模型下载 502 | 国内网络 | `HF_ENDPOINT=https://hf-mirror.com`，`HF_HUB_DISABLE_XET=1` |
| 3 | `av` 库 `metadata_errors` 报错 | 版本不兼容 | 锁定 `av==13.1.0` |
| 4 | ffmpeg concat 失败 | 相对路径 | 文件列表必须写**绝对路径** |
| 5 | 合成进程被杀（exit 137） | 前台运行 OOM | **必须后台运行** |
| 6 | medium 模型边界漏转写 | 模型特性 | 回退 `small` |
| 7 | `GAP_THRESHOLD=1.5` 误判 | 阈值过小 | 调到 `4.0` |
| 8 | `eq=brightness=0.82` 过曝全白 | 加性偏移，非乘法 | 移除 eq，改字幕配色 |
| 9 | concat 拼片头片尾丢片尾文字 | 滤镜拼接时序 | 改单视频流（V3 已彻底去掉片头片尾） |
| 10 | 挖空下划线重叠 | em space + `\u1` 作用范围错乱 | 改单条连续下划线 + 普通空格 |
| 11 | 长句左右被裁切 | libass `\q2` 折行不可靠 | Python 手动折行插 `\N` |
| 12 | 高亮颜色跨行断裂 | 先加标签后折行 | 改为先折行后逐行高亮 |
| 13 | 背景左右黑边 | `decrease+pad` 留边 | 改 `increase+crop` 铺满 |

## 6. 架构局限与改进方向

| 局限 | 影响 | 可选改进 |
|---|---|---|
| 手动折行靠估算宽度 | 字体变化时需重调系数 | 接入 PIL `font.getlength()` 精确测量 |
| whisper 转写可能不完美 | 原文与转写差异大时对齐率下降 | 增加对齐失败告警阈值 |
| 中间产物共用 `data/` | 批量处理时逐篇覆盖，无法并发 | 按素材名分目录隔离 |
| 无断点续跑 | 任一步失败需从该步重跑（可手动） | 增加产物存在性检查跳过已完成步骤 |
| `00_background.py` 会覆盖浅色背景 | ⚠️ `batch.sh` 调用它生成**深色**渐变背景，会覆盖现有清新浅色背景图 | 从 `batch.sh` 移除该调用，或改脚本逻辑 |
| API Key 硬编码 | 密钥泄露风险 | 移入环境变量并设为必需 |
